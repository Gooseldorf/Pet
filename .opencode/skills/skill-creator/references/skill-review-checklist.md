## Skill Review Checklist

Use this checklist before considering a skill finished.

### Scope

- Does the skill solve one coherent job?
- Is it broad enough to be reused?
- Is it narrow enough to trigger accurately?

### Triggering

- Does `description` say what the skill does?
- Does `description` say when to use it?
- Does it include realistic trigger words?
- Would a near-neighbor skill be more appropriate in ambiguous cases?

### Body quality

- Is the workflow obvious?
- Are decision points explained?
- Are outputs or expectations clear?
- Is the main file lean enough to load on demand?

### Resource hygiene

- Are large details moved into `references/`?
- Are deterministic helpers moved into `scripts/`?
- Are all referenced paths real?
- Are there unused files that should be removed?

### Maintenance

- Would another engineer understand how to extend the skill?
- Is there any project-specific assumption that should be called out explicitly?
- Does the skill avoid unnecessary complexity?
